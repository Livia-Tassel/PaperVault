# PaperVault 架构

## 状态
当前开发版本为 0.2.2，包含阅读工作台与可追溯笔记；实际安装验收以[总测试报告](../verification/TEST_REPORT.md)为准，公开下载状态见[发布说明](../RELEASES.md)。开发经过保留在[历史进度](../archive/PROGRESS.md)。

## 边界
React/TypeScript 提供中文桌面界面；Tauri 2 管理原生交互与 Python Sidecar；FastAPI 只监听回环地址，按每次启动的令牌鉴权。后台解析在独立进程中执行，SQLite 是元数据与索引的唯一事实来源。

## 持久化
原件复制到 `papers/<uuid>/original.pdf`，源文件不修改。自动解析结果放在不可变 revisions 目录，人工覆盖单独记录。发布采用同卷临时目录、文件校验、目录重命名、数据库最后提交的协议。SQLite 与文件系统不具备联合事务，启动恢复处理未引用结果。SQLite 使用 WAL、FULL 同步、外键及单库进程锁。

## 搜索与定位
FTS5 使用应用层中英预分词。原文和高亮片段独立处理。资源位置保存未旋转 PDF user-space 坐标与原始 provenance，PDF.js 使用 viewport 正逆变换定位，PDFium负责渲染。

## 阅读与笔记
`reading_states` 保存每篇论文的阅读位置、PDF锚点、额外旋转、缩放模式、阅读状态及最近打开时间。它不经过论文元数据修改路径，滚动保存不会重建整篇全文索引或产生人工解析文件。

`annotations` 保存书签、高亮、笔记以及逐行/跨页来源矩形。笔记内容与原文摘录分开，删除采用可恢复标记；版本号与 `expected_version` 在同一事务比较，过时请求返回409。笔记CRUD和FTS同事务，论文全量重建索引也包含有效笔记。备份包含这两个表；重新解析不改用户笔记。

前端将阅读视图变更合并为串行保存，导航/原生关闭先等待待保存进度。冲突时明确选择保留当前视图或采用服务端记录；后者同时重建实际阅读器视图。元数据、目录、资源及笔记使用统一编辑守卫，保存失败不会执行离开动作。

多论文会话、集合筛选和滚动/焦点按 `library.id + library.path` 缓存在本机，鉴权令牌不落盘。跨库时卸载视图、清理操作对象；写请求携带百分号编码的库上下文，后端用异步互斥锁把上下文检查与库写操作/切库串行化，防止相同UUID的恢复副本接收旧请求。

阅读器只挂载活动论文；每页画布限制16,777,216像素和8192最长边，离开近视口后释放位图。文字层使用PDF.js的完整缩放变量和文档语言；保留已访问文字层以支持跨页选择。高倍缩放需要降低位图采样时显示实际状态，PDF坐标、文本与选区几何不随位图预算改变。

## 技术选择
Docling 完成真实版面与表格识别，PDFium替代PyMuPDF避免引入其AGPL/商业许可选择。SQLAlchemy/Alembic负责迁移，直接 sqlite3 事务适配层负责FTS与备份API。PyInstaller onedir 保留原生依赖目录；模型独立管理，正常解析禁止隐式网络下载。

## 扩展
Parser接口隔离引擎；AI Provider只预留协议，核心使用不需要API Key。P2不计入首版验收。
