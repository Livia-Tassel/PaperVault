# 已知问题与后续工作

## 固有适用范围
- 数字原生PDF优先；默认关闭OCR，扫描论文可能没有可搜索正文。
- 复杂排版、图注分离与跨页表格可能识别不完整。界面保留原文定位、警告及人工修正入口。
- CSV不能表达合并单元格和视觉布局，应同时保留HTML和PNG。
- 基础表格编辑器使用行列网格；编辑合并表格前会提示结构转换，原自动解析版本和原PDF截图继续保留。
- 自动元数据只保存具有来源证据的字段；年份、作者、DOI等可能为空。
- 未提供代码签名证书；本地构建的Windows安装包为未签名版本。
- 原创嵌入图回归中，模型裁剪有时不包含图片内部的顶部标题；可通过PDF框选修正。原始JPEG仅在与单一嵌入对象明确对应时额外保存。
- 公开9页Docling报告检测到5个图片区域和3个表格区域；其中无Caption区域、截图与Figure/Table类型冲突需要校对。这是检测输出数量，不是准确率声明。

## 0.2 阅读边界
- 书签、高亮和笔记独立保存在论文库中，不写回PDF标准注释层；其他PDF阅读器不会自动显示这些笔记。可导出JSON/Markdown或整篇资源包。
- 单次文本标注最多512个矩形、20,000字摘录；过长选区需分段记录。已删除记录不参与全文检索，但可按论文/类型/标签浏览恢复。
- 极大页面/800%缩放会限制每页位图尺寸；此限制不等同于整个WebView进程的内存上限。81页极端测试的完整浏览器RSS曾达到约1.15GB，详见性能记录。
- 单页预览位图最多16,777,216像素、最长边8192像素；实际降采样时界面会提示清晰度降低。远离视口的位图与批注覆盖层会回收，但已访问的文字层保留以支持跨页选区，长文档的文字结构、PDF.js缓存和浏览器开销仍会占用内存。
- 1,000条合成批注（同一双页PDF、3,000个矩形）修复后的生产构建测试中，完整Edge进程树工作集采样达到约1,006 MiB；这是浏览器/GPU/辅助进程合计，不是WebView独占或固定上限。一次缩放仍出现109 ms主线程长任务，打开/缩放耗时没有在该次对比中改善。持续滚动优化不代表所有操作无停顿；更低配置和更大批注量尚无等价实测结论，详见测试报告的批注规模验收。
- 正常导航与原生关闭有未保存保护；强制结束进程或断电仍可能丢失尚未提交的编辑草稿。已经成功保存的阅读记录和笔记按数据库事务持久化。
- 0002数据库不能直接交给旧版0.1.x程序打开。回退应使用升级前完整备份，新库需保留以免丢失新增笔记。
