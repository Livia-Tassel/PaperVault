# 真实论文补充测试（2026-10-09）

本轮新增下载6篇真实论文，与原Docling报告一起测试，共7篇、71页。所有样本来自出版方或arXiv，有明确开放许可和PDF哈希；完整PDF、附录均纳入，另附补充材料不在范围内。样本有针对性地覆盖双栏、单栏、多子图、显微照片、多级表头、跨页长表和合理零图表结果，不是随机抽样，不能据此声称通用准确率。

软件流程与内容准确性分开评估。0.2.0已安装后台真实离线解析7篇，54个自动资源的可读导出、Caption检索、原PDF哈希和位置范围检查通过；独立副本的编辑、备份恢复、重启也通过。逐页人工对照仍发现明确识别缺陷。针对其中一个软件元数据问题提供0.2.1修复；其他模型和PDF文字层限制没有假称解决。

## 人工基准与质量边界

三份独立基准先依据原始PDF逐页渲染建立，再查看解析结果。所有71页源页面、54个自动资源PNG，以及25份Table CSV/HTML均检查。参照共16个Figure、22个逻辑Table；Docling附录里嵌套的另一篇论文图表不重复计作本论文科研对象。

- 完整主体可见：37/38个逻辑图表。仅按单个资源完整保留时是36/38，因为PRISMA有一张跨页表拆成两份。此项只判断视觉主体内容，不证明单元格结构/字义正确。
- 完整编号与图注关联：34/38。关联正确也可能有错误Unicode字符或连词空格丢失。
- 60个预先选定的语义行列单元格：49个逐格式精确一致，1个CSV短横线经过防公式注入转义后等价，10个失败。失败项来自Docling Table 1，单元格把两种线程配置的值合在一起；不能因为包含正确数字子串就算正确。
- 另外确认BERT Table 3与Sentence-BERT Table 2结构错误。这两处不在预选30个ML单元格中，因此抽查成功不能掩盖整表结构问题。PRISMA首段还丢失部分合并单元格跨度。
- 13个资源属于出版或软件标志，单列为图库噪声；Docling另3个资源属于外层Figure内部的碎片。没有把辅助图片算作额外正确科研图，也没有用原始资源数量冒充检出准确率。
- 一个被误分为Table的截图片段没有结构化行，CSV为空、HTML是空表。接口返回成功和文件格式可解码并不表示有可用表格数据；该项已作为失败的外层Figure和嵌套碎片记录。

## 原PDF字形与文字层不一致

显微论文里，视觉上的微量单位、负号和乘号在可提取文字中变成mg、2、6。独立使用PDFium直接读原PDF、完全绕过Docling和导出接口，也得到相同错误Unicode。PNG中的可见字形仍正确。

这不是CSV文件写坏了，也不能靠把所有mg都替换成微克解决。当前默认不做OCR，科研使用时应对照PDF或PNG核对单位、符号和行列。20个科学论文预选数据单元格虽然通过，未包含这些错误表头/符号，不能推出整表正确。详细复现见 `source-text-layer-diagnosis.json`。

## 已修复的标题错误与0.2.1

旧版对显微论文采用了内部PDF标题 `pone.0031638 1..8`，挡住了已经识别出来的首页真实标题。0.2.1仅保守排除这类“出版导出标识+页码范围”，使用摘要前的明确原文标题并保留来源标记；无可信候选则留空，普通描述性PDF标题保持原规则。不会从文件名编造标题，也不覆盖人工标题。

新增回归先重现2个失败，修复后6项定向测试通过。使用7篇原始Docling块与PDF元数据重放，只有目标论文的title/title_source变化，其余6篇所有元数据不变。完整后端120项通过、0跳过，包含5项用合成PDF真实执行Docling的既有用例；这5项不算另外5篇外部论文。

随后新冻结0.2.1后台重新执行BERT和显微论文的真实模型解析，29个资源检查、独立副本备份恢复和重启通过。真实标题已修正。与旧基线相比，29张300DPI PNG哈希、Caption和Table数据相同，所有科研对象坐标相同；一枚辅助页脚logo的坐标有约0.000007621 PDF point的浮点差，PNG字节不变，如实保留在对照记录。

最终0.2.1已实际安装，原有两套原生验收与新增两篇真实论文窗口验收全部通过。显微论文的API标题和界面标题都与出版方标题精确一致；科研图/表定位、笔记书签与重启回读通过。11项随包文档、846个许可证文件、7个源码归档逐文件哈希一致。

## 桌面流程与原生诊断

已安装0.2.0的真实Tauri窗口分别打开BERT与显微论文，验证PDF位图/页内查找、科研图和表的详情及原文区域、页2书签/笔记、退出和重启回读。最后补测选择有Caption的科研图，避免只截图首页logo。测试用独立备份副本，原自动基线不变。

120项源码组合回归再次打印两条Windows access violation诊断，只有docling_parse路径碎片，之后120项全部通过、进程exit0。一次保留faulthandler的5项真实parser分组复验为5 passed、exit0且没有新诊断；根因仍未定位，不能宣称已修复或无害。7个安装版worker日志没有同类诊断，但没有独立记录每个worker退出码和同等强度的faulthandler启用状态；可确证的是job完成、输出校验通过、后台主进程正常退出。完整边界见 `native-diagnostic-review.json`。

首次批量测试还暴露两个测试工具问题：PATCH论文响应与GET响应的扩展字段不同，旧断言误把 `similar_papers` 差异当数据丢失；新增书签后进入编辑器，旧原生测试定位器错误地寻找另一页面按钮。已保留失败证据，仅修正测试路径；通过独立副本复验，没有重跑模型或修改基线来掩盖失败。
